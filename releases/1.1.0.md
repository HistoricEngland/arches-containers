# Arches-containers tool (act) 1.1.0 Release Notes

## Bug Fixes and Enhancements

> ℹ️ Only Arches-container templates for Arches 7.6, 8.0, and 8.1 have been updated in this release.
> If you are using an older version of Arches, you can continue to create act projects using the existing templates, but any issues that arise will need to be addressed by the developer.
> Best endeavours have been made to ensure backward compatibility for existing act projects, but it is recommended to update to the latest templates when possible to take advantage of new features and fixes.

### Notable Changes

- Adds support for Arches 8.1 [#92](https://github.com/HistoricEngland/arches-containers/pull/92).
- Removes the `init` command — initialisation is now performed automatically by `up` when a project has not yet been initialised [#87](https://github.com/HistoricEngland/arches-containers/pull/87).
- Adds a `shell` command to open an interactive shell inside a project container, with a `--exec` option for running non-interactive commands from scripts [#90](https://github.com/HistoricEngland/arches-containers/pull/90).
- Adds a `logs` command to view container logs, with a `--follow`/`-f` option to stream output in real time [#90](https://github.com/HistoricEngland/arches-containers/pull/90).

### Other Changes

- Fixes an issue with the service startup check incorrectly thinking the project service was available [#83](https://github.com/HistoricEngland/arches-containers/pull/83).
- Adds warnings when creating templates for unsupported arches version templates [#85](https://github.com/HistoricEngland/arches-containers/pull/85).
- Adds a hash to act project files and docker generated objects to allow for multiple instances of projects with the same name to exist without impacting each other [#83](https://github.com/HistoricEngland/arches-containers/pull/83).
- Adds new CLI argument for specifying the local repository name when creating a new project [#75](https://github.com/HistoricEngland/arches-containers/pull/75).
- Fixes webpack container running front end build before the project service is available [#83](https://github.com/HistoricEngland/arches-containers/pull/83).
- Adds support for "kebab-case" repository names [#75](https://github.com/HistoricEngland/arches-containers/pull/75).
- Adds DeepWiki link to the README [#75](https://github.com/HistoricEngland/arches-containers/pull/75).
- Changes CLI banner to be more compact [#75](https://github.com/HistoricEngland/arches-containers/pull/75).

## Installation Instructions

Activate your environment and run the following command to install the latest version of arches-containers:

```bash
pip install --upgrade arches-containers
```

## Updates to act project configurations

Existing act configurations should continue to work as is.

For act projects using version 7.6 templates and above, it is recommended to recreate the project configuration using the latest templates to take advantage of new features and fixes.

There is no automatic migration for existing act project configurations, so this will need to be done manually. 

> ‼️ Before proceeding, you will need to make a backup of your database as the steps below will create a new database volume, so you will need to restore your database backup into the new volume after the new configuration has been created.

Manually change the name of you act project directory (`.arches-containers/<project_name>`) to a new name and then run the `act create` command with the original project name and the `--activate` flag to create a new configuration with the same name and activate it. For example, if your original project name was `my_project`, you could rename the project directory to `my_project_old` and then run:

```bash
# if your original project used the 7.6 template
act create -p my_project -v 7.6 --activate
```

You will then need to manually update the new configuration with any custom settings from the old configuration, such as environment variables or custom service definitions. Finally, you can remove the old project directory once you have confirmed the new configuration is working correctly.

The new act project will use a kebab-case repository name, so you will need to manually rename the repo directory to match the new `project_repo_directory` value in your act project configuration. For example, if your `project_repo_directory` is `my-project`, your local repository folder should also be named `my-project`.

You no longer need to run `act init` as all initialisation steps are now performed automatically by `act up` when a project has not yet been initialised, so you can simply run `act up` to start the project after updating the configuration.

If you have previously imported this act project from the repostiory, don't forget to export it back into your repository after updating the configuration to ensure the latest configuration is saved.
